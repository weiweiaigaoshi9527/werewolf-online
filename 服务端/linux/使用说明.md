# 狼人杀 Online · 服务端（Linux x64）

内置 **Java 21 运行时**，无需在系统里安装 Java。解压即用。

---

## 一、快速开始

```bash
tar -xzf werewolf-server-1.0.0-linux-x64.tar.gz
cd werewolf-server
./start.sh
```

启动后终端会打印：

```
本机访问:   https://localhost:11111
局域网访问: https://192.168.1.23:11111    <-- 把这个地址发给玩家
后台管理:   https://localhost:11111/admin  （首个注册账号即管理员）
```

玩家用**浏览器**或游戏客户端打开上面那个「局域网访问」地址即可开黑。
首次进入自签证书会提示「不安全」，点 **高级 → 继续访问** 一次即可（每台设备一次）。

停止：在启动窗口按 `Ctrl+C`，或另开终端执行 `./stop.sh`。

## 二、目录结构

```
werewolf-server/
├── start.sh               一键启动（前台运行 + 崩溃自动守护）
├── stop.sh                停止服务
├── install-service.sh     注册为 systemd 常驻服务（需 root，推荐服务器用）
├── uninstall-service.sh   卸载 systemd 服务
├── jre/                   内置 Java 21 运行时（Temurin）
├── werewolf-online.jar    服务端程序（Spring Boot 3.5 + H2）
├── config/keystore.p12    自签 HTTPS 证书（缺失时 start.sh 会用 openssl 自动生成）
├── data/                  H2 数据库（账号、战绩、房间数据）——删除即重置
├── uploads/               玩家上传的头像
└── logs/                  运行日志
```

## 三、常用参数（环境变量）

| 变量 | 默认 | 说明 |
|---|---|---|
| `WW_PORT` | `11111` | 监听端口 |
| `WW_HEAP` | `1024m` | JVM 堆上限（人少可降到 512m，人多可升到 2048m） |
| `WW_BIND` | 全部网卡 | 只监听指定地址，如 `WW_BIND=0.0.0.0` |
| `WW_VOICE_HOME` | 自动查找 | 语音微服务目录（见第七节） |
| `WW_VOICE_WAIT` | `15` | 启动时等待语音服务就绪的秒数 |

示例：

```bash
WW_PORT=11222 WW_HEAP=2048m ./start.sh
```

## 四、系统要求

- Linux x64（glibc 2.17+），Ubuntu / Debian / CentOS / Fedora / Arch 等主流发行版均可
- 内存 ≥ 1 GB 空闲（服务端常驻约 300–500 MB）
- 磁盘 ≥ 1 GB（数据库与头像会持续增长）

## 五、常驻运行（推荐服务器用）

```bash
sudo ./install-service.sh          # 注册并开机自启
sudo systemctl start werewolf-server
journalctl -u werewolf-server -f   # 看日志
```

## 六、公网部署（跨地互通）

局域网直接 `./start.sh` 即可。要让外地玩家连上，推荐
**Nginx 终结 TLS + 反向代理到 127.0.0.1:11111**，做法与证书自动续期
详见工程内 `werewolf_app/DEPLOY-server.md` 的 B 节。

要点：反向代理必须给 `/ws` 与 `/ws/voice` 打开 WebSocket 升级头
（`Upgrade` / `Connection: upgrade`）并把 `proxy_read_timeout` 调到 3600s，
否则游戏状态同步与语音会断连。

## 七、语音（TTS / ASR）说明

语音同传（真人说话 → 识别 → 用座位音色重新朗读；AI 逐句发声）靠两个本地 Python
微服务实现：**SenseVoice**（ASR，端口 5001）+ **Kokoro**（TTS，端口 5002）。

它们的运行时体积很大（Python + torch + 模型，共数 GB），所以**不随本包分发**，
需要单独准备。`start.sh` 会按下面顺序自动查找语音目录，找到就拉起两个服务并启用语音：

1. 环境变量 `WW_VOICE_HOME` 指定的目录
2. 本目录下的 `voice/`
3. 本目录**上一级**的 `werewolf-voice/`（即和工程目录并排放）
4. `~/werewolf-voice/`
5. `/opt/werewolf-voice/`

命中的目录里需要有：`asr_service.py`、`tts_service.py`、`venv-asr/`、`venv-tts/`、`models/`。

**怎么准备语音目录**：语音服务本身是跨平台的 Python 程序（FastAPI + funasr + kokoro），
但本工程现有的安装脚本是 Windows 版（`voice\install_voice.bat`）。Linux 上可参考它手工搭建：

```bash
python3.11 -m venv venv-asr && ./venv-asr/bin/pip install torch torchaudio funasr modelscope soundfile numpy fastapi "uvicorn[standard]"
python3.11 -m venv venv-tts && ./venv-tts/bin/pip install kokoro "misaki[zh]" soundfile numpy fastapi "uvicorn[standard]" "huggingface_hub[cli]"
# 再下载模型到 models/SenseVoiceSmall、models/punc_ct、models/hf（Kokoro-82M），
# 并把工程 voice/asr_service.py、voice/tts_service.py 放到该目录
```

判断成功的标志：启动时终端会打印 `语音同传: 已启用（...）`；找不到则打印
`未检测到语音微服务`，此时除麦克风外一切功能正常。

说明：

- 纯文字模式完全可用；只有「浏览器麦克风 / 语音同传」需要语音服务。
- 麦克风还要求 HTTPS（本包默认用 openssl 生成自签证书并走 HTTPS）。
- `stop.sh` 只会停**本目录这次启动的**语音服务（记录在 `logs/voice-pids.txt`），
  不会去动别的实例已经在跑的 ASR/TTS。
- 首次启动语音要加载模型，可能等几十秒；期间页面会显示「语音服务未就绪」，稍后自动可用。

## 八、FAQ

- **端口被占用**：`WW_PORT=11222 ./start.sh`
- **忘记管理员账号**：删除 `data/` 目录重启即清空全部数据（谨慎），第一个注册的账号会成为管理员
- **局域网连不上**：确认防火墙放行端口，例如 `sudo ufw allow 11111/tcp`
- **证书告警**：自签证书属正常现象；换网络后 IP 变了，删除 `config/keystore.p12` 再启动会重新生成
