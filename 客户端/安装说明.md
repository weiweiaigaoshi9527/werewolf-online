# 狼人杀客户端 · 安装与说明

版本 **1.1.0**（三端 Flutter 原生客户端）。服务端端口是 **11111**（HTTPS 自签证书），
不是早期的 8080——填地址时注意。

## 目录内容

| 文件 | 用途 |
|---|---|
| `狼人杀客户端-1.1.0-windows-x64.zip` | Windows 10/11 x64 便携版，解压即用 |
| `狼人杀客户端-1.1.0-android-arm64.apk` | 现代手机（arm64-v8a，绝大多数机型） |
| `狼人杀客户端-1.1.0-android-arm32.apk` | 老机型（armeabi-v7a） |
| `狼人杀客户端-1.1.0-linux-x64.deb` | Debian/Ubuntu x64 安装包（`apt install` 安装） |
| `狼人杀客户端-1.1.0-linux-x64-portable.tar.xz` | Linux x64 便携版，解压即用 |
| `实跑取证-windows大厅.png` / `渲染基线-P1房间双人组队.png` | 验证截图，非安装物 |

## Windows

解压到任意目录（**建议纯英文路径**），双击 `werewolf_app.exe`。
首次进入「服务器设置」，填：

- 本机自测：`https://localhost:11111`
- 局域网：`https://<服务端内网IP>:11111`
- 公网：`https://你的域名:11111`

保持「允许自签名证书」开启（自签证书场景必须；换成正式证书后可关掉）。
点「测试连接」通过后再「保存并进入」。

## Android

把 APK 传到手机安装，需要允许「未知来源」。

> ⚠️ 当前是 **debug key 签名**（`CN=Android Debug`），只适合自用侧载。
> 要上应用商店或做正式分发，需要另建 release keystore 并在
> `android/app/build.gradle` 的 `signingConfigs.release` 里配置，然后重新构建。

麦克风语音需要运行时授权，首次点麦会弹权限框；服务端语音微服务未启动时，
对局里的语音入口会自动隐藏（由 `game.state` 的 `voiceAvailable` 决定）。

## Linux

两个包都由 GitHub Actions 在 **ubuntu-22.04** 上构建（glibc 2.35），可在 22.04 及更新的
发行版上运行；更老的发行版（如 20.04）因 glibc 偏旧可能跑不起来。

### deb（Debian / Ubuntu）

```bash
sudo apt install ./狼人杀客户端-1.1.0-linux-x64.deb
werewolf-client            # 或从应用菜单点「狼人杀」
```

依赖会自动安装：GTK3 + GStreamer 运行库（`libgstreamer1.0-0`、
`libgstreamer-plugins-base1.0-0`、`gstreamer1.0-plugins-good`）。最后一项是**音效**所需——
对局音效走 GStreamer 播放运行时合成的 WAV，缺了它会静音。

### 便携版（任意 x64 Linux）

```bash
tar xf 狼人杀客户端-1.1.0-linux-x64-portable.tar.xz -C ~/ww
~/ww/werewolf_app
```

> 连自签证书的局域网服务端时，App 内「服务器设置」里保持"允许自签名证书"开启即可
> （Dart 侧 `HttpOverrides` 放行，不依赖系统 CA）。

### 自己重新出包

`.github/workflows/client-release.yml` 会一并产出三端：推一个 `v*` tag 即触发，
三个平台各自在官方 runner 上构建（Linux 在干净 `ubuntu:22.04` 容器里构建），
打 tag 时自动汇总成 Release 附件。也可在 Actions 页手动 Run workflow。

## 与旧客户端的关系

- **Electron 套壳（`G:\wwelectron`）已停用**：它加载网页版，体积大且**做不到安卓**，
  三端目标下不再构建分发。保留目录仅作历史参考（其服务器地址已由并行会话改到 11111）。
- **Capacitor 方案（`G:\wolfmobile`）作废**：与 Flutter 方案目标重叠，且桌面侧能力弱。
- **网页版 / PWA 继续保留**：它和客户端连的是同一套 `/api` + `/ws` 接口，
  互相之间天然互通，仍是最省事的入口。

## 出问题先看这里

- 连不上：确认服务端在跑（`https://<地址>:11111/api/health` 应返回 `{"ok":true}`），
  以及「允许自签名证书」是否开着。
- 安卓装不上：机型是 arm64 却装了 arm32 包（或反之），换一个包试。
- 语音没声音：服务端语音微服务（SenseVoice + Kokoro）要起来；
  App 侧的判定来自 `voice.hello` 的 `enabled`。
